# Security Policy

## Supported Versions

We actively release security and bug patches for the latest major version of **Unbound Music**:

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The Unbound Music team takes security, privacy, and code safety seriously. If you discover a security vulnerability or privacy concern within Unbound Music, please do **not** open a public issue.

### Safe Reporting Process

1. **Email Disclosure**: Send a detailed report to our security maintainers at:
   - **`blubrdpirts@gmail.com`**
2. **Details to Include**:
   - Description of the vulnerability or security flaw.
   - Affected components (e.g. Android client, Desktop runner, Embedded Go daemon, local storage).
   - Step-by-step instructions or proof-of-concept to reproduce the vulnerability.
   - Potential impact on user privacy or system security.

### Our Response Timeline
- **Initial Response**: We will acknowledge receipt of your vulnerability report within **48 hours**.
- **Assessment & Patch**: We will provide an assessment and timeline for a patch within **7 business days**.
- **Public Disclosure**: Once a fix is verified and released, credit will be given to the reporter in our release notes (unless anonymity is requested).

---

## Privacy Principles

* **Zero Telemetry**: Unbound Music does not track users, log IP addresses, or phone home to any central servers.
* **On-Device Sovereignty**: All audio fingerprinting, lyric synchronization models, and local databases operate strictly on the user's device.
